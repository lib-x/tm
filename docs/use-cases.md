# 使用场景：组合通用能力，不扩张核心

本文是非规范性应用设计参考。所有 profile 名、应用消息和实现方法均为示例，不属于 TMP schema 或 SDK 内置服务。TMP 只提供双向字节流、通用协商、流控、半关闭和终止；应用消息也可以沿用已有协议。

| 场景 | 应用如何使用现有能力 | TMP 不解释的内容 |
| --- | --- | --- |
| 终端 | 一个 Interactive 流传PTY字节，另一个流传应用自定控制；metadata关联业务session | resize、signal、exit code、终端恢复与进程管理 |
| 远程桌面 | 输入/control 使用Interactive；媒体流用Realtime；文件/大图用Bulk，可分多个link | 编解码器、画面分片、关键帧、输入事件、音视频时钟 |
| herdr/会话事件 | 应用选择事件profile，流内以已有JSON/Protobuf等格式传记录 | 事件type、session id、序号、游标、订阅、去重与恢复 |
| 文件传输 | Bulk流传文件字节；应用控制流/记录传元数据及确认 | 文件名、路径、大小、hash、进度、断点、持久化、原子提交 |
| 剪切板 | 小消息使用Interactive；大图片/附件使用Bulk或独立流 | MIME、格式协商、来源id、防循环、系统剪切板访问与授权 |
| 截屏 | Interactive请求，Bulk/Realtime返回图片；应用关联请求和响应 | 显示器、区域、分辨率、图片格式、屏幕权限与采集API |
| 中继发现与直连 | 先通过中继承载应用发现/协商流，再通过新Transport建新TMP link | peer目录、候选地址、NAT穿透、连接选择、身份凭证、路由与fallback |

## 终端与桌面

同一条流的 FIN 只表示发送方向 EOF，不代表进程退出、画面会话结束或远端已经消费。应用若拆分IO与控制，两流之间没有顺序保证；需要“退出事件一定晚于尾部输出”时，应用必须定义偏移/栅栏或把相关记录放在同一条有序流内。

class 是调度提示，不能消除底层可靠载体的阻塞。应用可以在编码/排队前丢弃过期视频帧，不能删掉已经发送的一部分业务记录。低延迟不可靠媒体应选择另外的媒体/Transport 方案；不把新增 DGRAM 强塞进本版核心。

## 文件、剪切板与截屏

DATA 帧边界不等于文件块或消息边界。应用已有协议可直接放进流；若自定义记录，必须有自身长度上限及增量解析，并在读取部分字节时及时 consume。TMP 的 WINDOW 仅表示接收端释放内存，不表示文件已 fsync、剪切板已写入或用户已看到截图。需要业务确认时在应用流中定义确认。

断点续传由应用保存文件身份、偏移、hash和持久化状态；TMP链路重建不隐式恢复。路径授权和防目录穿越由文件应用负责，不能把 `Open.route` 或 metadata 直接当任意文件路径/命令。剪切板应用要自己控制MIME、大小、来源去重和授权；截屏应用要自己控制请求权限和数据披露范围。这些属于应用集成合同，不产生核心字段。

## 中继发现后直连

有两类中继，应用必须区分信任模型：

1. 字节转发中继只转发端到端加密的Transport字节，端点之间只有一个TMP链路，中继不能读取TMP内容。
2. 终止TMP的broker维护A↔R、B↔R两条独立链路，应用在broker上完成注册、发现、授权、信令转发；R能看到应用数据，除非应用另做端到端加密。两条链路的stream id/window不能直接共享。

发现/直连的一种应用流程：

1. A、B分别认证到R，应用登记服务并按权限发现对端。
2. 通过普通应用流交换带过期时间的候选信息。ICE/STUN/TURN、WebRTC或受控网络的直接地址由适配器实现；SSH/WS/QUIC任意名字本身不保证NAT可达。
3. 尝试建立A↔B的Transport，独立验证对端身份及双方授权；不得把候选地址或broker声明当作身份。限制候选地址目的范围，避免应用被用作任意拨号代理。
4. 成功后在新Transport上重新执行TMP Hello/Welcome；应用选择将新业务放在直连或中继链路。可达失败继续中继。并行成功时由应用选定一条，关闭多余连接，避免重复执行。
5. 活跃流默认留在原链路直到结束；如应用需要迁移，自己定义检查点和幂等恢复。不复制旧stream id、信用或未确认写操作。

这些能力无须新增 Rendezvous/Relay/Candidate 核心消息。未来增加新的发现服务、NAT方案或传输库仍然只是应用/适配器变化。

## 未来场景的验收原则

先尝试用现有OPEN、双向字节流、class和应用私有metadata组合。只有出现跨场景、不可由上层表达、且有充分互通证据的通用问题，才考虑核心演进；新增场景本身不是增加核心功能的理由。
